Bear Street can operate on local worker/PID state without first reconciling it against Redis and process liveness.

Today's issue relevance:
IMPORTANT / POSSIBLE CAUSE.

3. IMPORTANT / POSSIBLE CAUSE - Redis PID handling differs

Bear Street location:
mintzy-bear-street/session_manager.py:482

Why this is important:
The reference explicitly checks the shared Redis PID during cleanup.
Bear Street resolves PID through its own helper, which may involve local PID storage and can behave differently if Redis PID and local PID file disagree.

Today's issue relevance:
IMPORTANT / POSSIBLE CAUSE.
In multi-worker or restarted API-server flows, Redis is the shared source that tells whether another process still owns the session.
Any mismatch here can affect whether simulation is considered fully stopped before live trading starts.

4. IMPORTANT / POSSIBLE CAUSE - final stopped verification differs

Reference reconciles again after attempting to stop/kill the worker:

mintzy-bear-street/session_manager.py:493

Today's issue relevance:
IMPORTANT / POSSIBLE CAUSE.

stop_simulation_session() itself matches the reference, but the cleanup function it relies on is different.

Most important possible causes:

1. Bear Street ensure_worker_stopped() does not start with _reconcile_session_registry(session_id).

Gateway autoStopDueSimulations() daily latch comparison
======================================================

Files compared:
- mintzy-api-gateway/modules/bear_street/services/plugin.simulation.service.js
- mintzy-api-gateway/modules/angle_one/services/plugin.simulation.service.js

Function compared:
autoStopDueSimulations()

Status:
SUGGESTED IMPROVEMENT ONLY.
Do not treat this as a Bear Street bug right now because the same behavior exists in the working angle_one reference module.

Reference behavior:
Angle One sets lastAutoStopDateKey = today before looping through all due simulation sessions.

Bear Street behavior:
Bear Street also sets lastAutoStopDateKey = today before looping through all due simulation sessions.

Difference:
No meaningful logic difference.
Bear uses broker: BROKER_KEY, where BROKER_KEY = "bear_street".
Angle One uses broker: "angle_one".

Risk:
If one session fails during the 1 PM auto-stop/live-handoff loop, the in-memory daily latch can prevent another automatic retry for the same trade date.

Reason not fixing now:
This appears intentional/reference-aligned because it prevents repeated auto-stop calls from hitting the plugin VM again and again after 1 PM.
Since angle_one has the same latch behavior and is being treated as the correct reference logic, Bear Street should keep this behavior for now.

Possible future improvement:
If needed later, gateway can track retry state per session instead of one global daily latch.
That would allow failed sessions to retry without repeatedly touching sessions that already completed successfully.
